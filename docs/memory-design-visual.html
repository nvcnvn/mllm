One arena, one unit size

A visual walk through docs/memory-design.md: what the hardware gives us, how the arena is cut into 1 MiB units, and what happens to those units, step by step, in six everyday situations.

  • One buffer for all per-token state. Full-attention pages, window pages and linear-attention state all live in one MTLBuffer of equal 1 MiB units.
  • Any free unit serves any need. No bands, no ratio setting, nothing to compact. An object's units don't have to be adjacent; the GPU finds each through a step table.
  • Units never move. address = slot × unit + offset. No virtual ids, no translation table.
  • One capacity question. Every caller goes through admit(n). Once admitted, a request's alloc() cannot fail.
  • Free now, reuse later. A released unit waits in pending until the GPU step that might read it has finished.

1 · What the machine gives us

CPU, GPU and Neural Engine share one pool of LPDDR5X. A Metal buffer in StorageModeShared is the same physical 16 KiB pages mapped into both the CPU's and the GPU's page tables, so there is no copy. Everything below is about how we carve that pool up.

2 · The arena

The arena is N equal units; slot s starts at byte s × unit. Every kind of state is a whole number of units, and the units of one object can be anywhere. Below is a snapshot (taken from scenario 3) with the encoding used in every figure on this page.

How big is a unit?

Example model: 8 full-attention layers, 24 window layers, 8 KV heads, head size 128, fp16, 32 tokens per page. One unit holds G layers, and G defaults to the number of full-attention layers, so a full-attention page is exactly one unit with no waste. Pick any coordinate and see where its two bytes live.

3 · A unit's life

Each slot has two counts, req_refs (live requests) and cache_refs (prefix-cache entries). A unit is reusable only when both are 0 and the GPU is done with it. All bookkeeping is plain CPU arrays on one scheduler thread, no locks.

4 · The one capacity question

A new request, a generation top-up, a load from SSD and a cache state copy all ask the same thing:

fits(n):      n ≤ free_units − reserved
can_ever(n):  n ≤ free_units + cache_only_units − reserved

admit(n):
    if not can_ever(n): return WAIT        # evict nothing
    while not fits(n): evict the cache's next victim
    reserved += n

n = pages for the uncached part of the prompt, plus a generation allowance, plus the request's bounded state (window ring with one page in transit, or one state slot). Each later alloc() takes one unit out of the request's reservation, and since reserved ≤ free_units always holds, it cannot fail. In the scenarios below the capacity bar shows these quantities live.
